# iOS app (SwiftUI)

Native SwiftUI app for iPhone (iOS 17+, Swift 6), offline-first with live round sync. SwiftData is the local store. See [../docs/architecture.md](../docs/architecture.md) for the client design and conflict strategy.

## Commands

```
open ios/Wad.xcodeproj          # build and run from Xcode
ios/scripts/test.sh             # build + test on the first available iPhone simulator
ios/scripts/test.sh -only-testing:WadTests/RoundStoreTests   # a single suite
ios/scripts/test.sh -only-testing:WadUITests                 # only the UI walkthrough
```

## Project file

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. The generated `Wad.xcodeproj` is committed, so you only need XcodeGen when adding targets or changing build settings:

```
cd ios && xcodegen
```

Edit `project.yml` rather than the project in Xcode's target settings, or the change is lost on the next regeneration. New Swift files under `Wad/` or `WadTests/` are picked up by regenerating.

## Layout

- `Wad/` — app target: `WadApp` (entry point and SwiftData container), `RootView` (tab shell), `Models/` (SwiftData models and their mapping to the engine inputs), `Setup/` (new-round flow: `RoundDraft` with its validation, and the course, players and games steps), `Rounds/` (rounds list and round detail with progress and scorecard), `Scoring/` (`RoundScorer` records scores, Wad makers and greenies and saves each change; `RoundStatus` is the engines' view of the round; the hole-by-hole scoring screen), `Settlement/` (`RoundSettlement` is what the settlement screen shows: the engine's payments, net positions and per-game results, provisional until all 18 holes are scored; an unresolved skins carryover is shown and never paid), `Engine/` (`EngineBridge`, which runs the TypeScript game engines in JavaScriptCore), `Resources/engines.js` (generated by `npm run build:ios-engines` in `backend/`; do not edit)
- `WadTests/` — unit tests (Swift Testing)
- `WadUITests/` — XCUITest walkthrough: sets up a round, scores all 18 holes by tapping and typing and checks the settlement against amounts worked out by hand, attaching a screenshot of each screen; `SetupValidationAndDeleteUITests` covers what each setup step shows when it cannot move on, and deleting a round from the list, including a relaunch on a store on disk
- `scripts/test.sh` — picks an available iPhone simulator so the same command works locally and in CI

Debug builds accept the launch argument `-debugSetupStep course|players|games|detail`, which opens the new-round flow at that step with a sample draft (`detail` creates the sample round and opens it). The flow also has a "Fill sample" button in debug builds. `-debugSeedRound finalPush` creates a finished round whose last holes push, to show the unresolved skins carryover. `-debugStoreFile <name>` keeps the store in a file of its own in the temporary directory, so that a UI test can relaunch the app on what it saved, and `-debugStoreCounts` shows the number of stored rounds, holes, players and scores under the rounds list.

The launch argument `-inMemoryStore` keeps the store in memory, so every launch starts empty; the UI tests use it. The tests run unsigned (`CODE_SIGNING_ALLOWED=NO`), which the simulator accepts for the UI test runner too.

The bundle id is `com.gillzj00.wad` and there is no signing team yet; both are set in `project.yml`.
