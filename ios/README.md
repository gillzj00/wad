# iOS app (SwiftUI)

Native SwiftUI app for iPhone (iOS 17+, Swift 6), offline-first with live round sync. SwiftData is the local store. See [../docs/architecture.md](../docs/architecture.md) for the client design and conflict strategy.

## Commands

```
open ios/Wad.xcodeproj          # build and run from Xcode
ios/scripts/test.sh             # build + every test on the first available iPhone simulator
ios/scripts/test.sh --unit      # the unit tests only (WadTests); what CI's unit-tests job runs
ios/scripts/test.sh --ui        # the UI tests only (WadUITests); what CI's ui-tests job runs
ios/scripts/test.sh -only-testing:WadTests/RoundStoreTests   # a single suite
```

Anything after the flag goes to xcodebuild, such as `-resultBundlePath`.

## Project file

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. The generated `Wad.xcodeproj` is committed, so you only need XcodeGen when adding targets or changing build settings:

```
cd ios && xcodegen
```

Edit `project.yml` rather than the project in Xcode's target settings, or the change is lost on the next regeneration. New Swift files under `Wad/` or `WadTests/` are picked up by regenerating.

## Layout

- `Wad/` — app target: `WadApp` (entry point and SwiftData container), `RootView` (tab shell), `Models/` (SwiftData models and their mapping to the engine inputs), `Setup/` (new-round flow: `RoundDraft` with its validation, and the course, players and games steps), `Rounds/` (the round history and round detail with progress, scorecard and the players' Venmo handles), `History/` (`RoundSummary`, what a history row says about a round, and the in-memory cache that keeps the engines from running for every row on every render), `Scoring/` (`RoundScorer` records scores, Wad makers and greenies and saves each change; `RoundStatus` is the engines' view of the round; the hole-by-hole scoring screen), `Settlement/` (`RoundSettlement` is what the settlement screen shows: the engine's payments, net positions and per-game results, provisional until all 18 holes are scored; an unresolved skins carryover is shown and never paid), `Payments/` (Venmo handles, the Venmo pay and request links, and the paid markers; see Payments below), `Theme/` (the design system: the colors, which are in the asset catalog with a light and a dark variant, type, spacing, the reusable pieces such as the card, the section header, the stat pill, the money label and the button styles, the scorecard marks of `ScoreNotation` and the illustration of the empty states), `Engine/` (`EngineBridge`, which runs the TypeScript game engines in JavaScriptCore), `Resources/engines.js` (generated by `npm run build:ios-engines` in `backend/`; do not edit)
- `WadTests/` — unit tests (Swift Testing)
- `WadUITests/` — three XCUITest smoke tests, each a few minutes on CI, attaching a screenshot of each screen: `RoundWalkthroughUITests` sets up a round by tapping and typing and scores its first three holes; `SettlementPaymentsUITests` pays and requests with Venmo on a seeded finished round (checking the link, without opening Venmo), marks payments paid and not paid, and checks the history row; `RoundDeleteUITests` deletes a round from the list, including a relaunch on a store on disk. The settlement amounts, the setup validation and the Venmo links are checked by the unit tests
- `scripts/test.sh` — picks an available iPhone simulator so the same command works locally and in CI; it first runs `scripts/test_select_device.py`. `--unit` and `--ui` run one of the two test targets; CI (`.github/workflows/ios-ci.yml`) runs them as the jobs `unit-tests` and `ui-tests`
- `scripts/make-app-icon.swift` — draws the app icon with CoreGraphics and writes the light, dark and tinted 1024 x 1024 PNGs of `AppIcon.appiconset` (`swift ios/scripts/make-app-icon.swift`)
- `scripts/install-device.sh` — builds for the iPhone that can be reached and installs the app. `scripts/select_device.py` picks the phone from `xcrun devicectl list devices --json-output`; a phone that is paired but unavailable is not used, and the script says to unlock it and connect it by USB or the same Wi-Fi

Debug builds accept the launch argument `-debugSetupStep course|players|games|detail`, which opens the new-round flow at that step with a sample draft (`detail` creates the sample round and opens it). The flow also has a "Fill sample" button in debug builds. `-debugSeedRound finalPush` creates a finished round whose last holes push, to show the unresolved skins carryover; `-debugSeedStartedAt <seconds since 1970>` sets its start. `-debugSeedRound gallery` creates three rounds (one being played, one finished with every kind of score, and the one with the carryover) and stays on the list. `-debugColorScheme light|dark` shows the app in that color scheme. `-debugLinkOpener opens|fails` opens no link: the link is recorded and shown on the payment sheet (`fails` behaves as if Venmo was not installed). `-debugStoreFile <name>` keeps the store in a file of its own in the temporary directory, so that a UI test can relaunch the app on what it saved, and `-debugStoreCounts` shows the number of stored rounds, holes, players and scores under the rounds list.

The launch argument `-inMemoryStore` keeps the store in memory, so every launch starts empty; the UI tests use it. The tests run unsigned (`CODE_SIGNING_ALLOWED=NO`), which the simulator accepts for the UI test runner too.

## Payments

On a final settlement (all 18 holes scored and no greenie left unpaid) each payment can be paid or requested with Venmo and marked paid. A provisional settlement offers neither.

- One phone scores for the group, so the app offers both: "Pay with Venmo" goes to the payee's handle, "Request with Venmo" is a charge to the payer's handle. Without the handle the action is disabled and the handle can be added there.
- The links are `venmo://paycharge?txn=<pay|charge>&recipients=<handle>&amount=<dollars.cents>&note=<note>` and, when the Venmo app cannot be opened, `https://venmo.com/<handle>?txn=<pay|charge>&amount=<dollars.cents>&note=<note>`. Venmo does not document them; the sources are cited in `VenmoLink.swift`. The amount is formatted from integer cents.
- The app moves no money and does not know what happened in Venmo: it asks before marking a payment paid. A payment can also be marked paid by hand.
- A paid marker belongs to the payment with its payer, payee and amount, like the backend's transfer id (`docs/api.md`). After a score correction a marker that matches no payment is listed as recorded before a correction, marks nothing paid, and can be removed.
- No entitlement or Info.plist entry is needed: the app opens the link and looks at the result instead of asking `canOpenURL`.

## Updating the app

`RoundPlayer.venmoHandle` and the `PaidMarker` model were added to the store. SwiftData migrates an existing store by itself (a new optional attribute, a new model and a new to-many relationship), so rounds are kept when the app is updated. `StoreMigrationTests` writes a store with the previous models and opens it with the current ones. To check by hand on a simulator: run the previous build with `-debugSeedRound finalPush -debugStoreFile check`, then the new build with `-debugStoreFile check -debugStoreCounts`; the round is in the list with its 54 scores.

The bundle id is `com.gillzj00.wad` and there is no signing team yet; both are set in `project.yml`.
